## 3. 接通工程师工作台

### 3.1 部署并开通身份

1. 与公共接口相同方式部署 `engineer-api` 和 `share-api`，依赖已锁定 `wx-server-sdk: 4.0.2`，入口均为 `index.main`。
2. 在“联系”页底部进入“工程师工作台”。`users` 集合存在且函数正常部署后，未授权用户会看到“复制我的身份标识”。
3. 由小程序管理员在云开发控制台手动添加 `users` 文档：

```json
{
  "_id": "替换为刚复制的完整 OPENID",
  "name": "店铺工程师",
  "role": "engineer",
  "status": "active"
}
```

`role: "engineer"` 只能管理自己创建的项目；`role: "admin"` 可以管理所有项目。开通管理员权限要明确确认人员，不能给普通顾客授权，不能把这条记录交由客户端自行创建。OPENID 不要发到公开页面或代码仓库。

停用人员时把 `status` 改为 `disabled`，并同时从下节的云存储上传名单移除。数据库角色和存储上传权限是两处独立配置。

控制台 v2.0.37 的默认添加表单将自定义文档 ID 限制为 24 字符，不能截断 OPENID 来适配。可在本机临时 `.json` 文件中每行写入上面的完整文档，向 `users` 使用 Insert 导入，随后核对完整 `_id`、role、status 和工作台实际返回。不要把含真实 OPENID 的文件提交到代码仓库。若 JSON 编辑器自动输入后记录为空，不能重复盲目提交，改用文件导入并验证结果。

### 3.2 配置云存储

文件分区：

- `public/`：仅存放获得公开展示许可的案例 / 微信二维码。
- `uploads/`：工程师直接上传的中转文件。
- `private/projects/`：由云函数登记保存的现场资料与生成结果，不向客户端直接开放读取。

尚未开放工程师上传时，可以先用 `cloudbase/rules/storage.json`：仅 `public/` 可读，客户端不可写。

需要上传时，在云存储 → 权限设置 → 自定义规则，使用 `cloudbase/rules/storage-engineer.example.json`，将占位符换成获授权工程师的真实 OPENID，再保存。该模板仅开放指定身份对 `uploads/` 的创建者写入，保留私有区不可读写。不要原样保存占位符，更不要改成全目录公开读写。规则生效后，实际上传一张获授权的 JPG / PNG 验证。

### 私有存储独立验收（不启动 AI）

开发版进入“开发联调测试项目｜非客户资料”，选择已保存位置后点击“验证私有存储（保留测试图）”。该入口和方法均检查开发版及指定项目，确认弹窗后才执行；体验 / 正式版隐藏。内置文件是程序生成的 320 × 200 色块 PNG，非现场照片、非案例，不使用用户提供的参考图。

## 4. 最后接通 AI，先小规模验证

免费云开发环境不等于已获得足够的生图资源。先在云开发控制台确认生图能力、当前环境的可用模型和资源额度；如需开通收费资源、升级或接受协议，由用户在控制台确认，不要自动开通。

当前 Provider 使用 `wx-server-sdk: 4.0.2` 的 `cloud.ai()` 和混元 `HY-Image-v3.0-I2I-ToB-v1.0.1`。AI 只由服务端 Worker 调用，不需要把密钥写入小程序。官方 I2I 接口最多一张参考图片；因此当前每个角度选一张对应现场照片，工程师将简图中的数量、分格、连接等要求转录为文字，材料 / 表面 / 颜色也以文字输入。上传的简图、材质参考仍会归档，但不会自动与现场照片一起输入模型。[官方 wx-server-sdk 生图说明](https://docs.cloudbase.net/ai/image-model/wx-server-sdk)

1. 确认 `generation_locks/image-worker` 已初始化，所有业务索引可用。
2. 首次先在控制台新建 `generation-worker`，选择普通事件函数、Node.js 20.19、入口 `index.main`，再上传本地代码与云端安装依赖；避免 CLI 自动创建为旧运行时。超时按生图官方建议设为 900 秒；若控制台不支持，先停止真实生图并核实限制，不要默认升级。已存在的函数不要为切换运行时直接删除重建。
3. 在环境级完整调用规则映射中保留 `"generation-worker": { "invoke": false }`。它也会在代码中拒绝带小程序身份的调用。
4. 默认不设置 `GENERATION_MODE`，此时 Worker 返回 `GENERATION_PAUSED`，不取任务、不调用模型。`config.json` 默认没有触发器。可先由管理控制台用 `{ "action": "preflight" }` 只读检查运行时、SDK 版本、AI 方法是否存在；此检查不证明生图额度或模型调用已通过，也不访问队列或调用模型。
5. 额度、超时、测试素材和首次调用范围确认后，设置环境变量 `GENERATION_MODE=manual`，仅在管理控制台用 `{ "action": "runOne", "jobId": "已确认的任务ID" }` 执行一张。任务必须由工程师确认页正常创建；只处理指定 queued 任务，不能使用空请求或定时事件意外消费其他队列任务。失败不会自动付费重试，单任务最多 3 次尝试。
6. 小规模质量验收完成并明确需要自动调度后，才设置 `GENERATION_MODE=scheduled`，参考 `cloudbase/generation-worker.timer.example.json` 手动配置 `image-queue`。该模式仅接受名为 image-queue 的 Timer 事件；每次最多处理一个角度。没有独立服务器，页面仍用“刷新进度”查看。

### 第一轮真实验收

使用获授权且已去除无关人员 / 门牌隐私的样本，先仅生成一个角度，明确会消耗生图资源：

1. 新建项目，添加阳台 / 卧室窗等位置；一个位置可选择多种产品。
2. 保存现场尺寸（毫米）、材料、表面处理、颜色和简图关键结构文字。
3. 上传对应角度现场照片与工程师结构简图；无需上传客户身份证等无关敏感资料。
4. 选择一个对应角度现场照片，进入“确认生成方案”页；核对结构摘要、材料、现场图与简图，勾选四项并确认资源消耗后提交任务。
5. 检查排队 → 生成 → 待审核；结果应保存为 `private/projects/.../renders/...`，默认不是已确认。
6. 核对数量、结构、材质、颜色、多角度一致性。明显违背结构要求的图片标记“需调整”，不能用于分享。
7. 审核通过后生成专属分享，以普通微信身份打开，确认只见指定预览，不见原始照片、简图、测量数据和工程师备注。
8. 停用分享，重新打开应不可查看；将已分享图片驳回后，也不再返回该图片。

已打开页面、截图和已取得的临时图片 URL 不能远程收回；临时 URL 目前签发 10 分钟。专属分享不是客户身份认证，任何拿到链接的人都能在有效期内查看并转发，工程师发送前应确认收件人。链接有效 30 天；只保存随机码哈希，原始分享路径只在创建后返回一次，离开页面后需要创建新分享，不会从后台恢复旧分享码。

改变安装位置的材料 / 结构要求后，旧图不能用于创建新的分享；旧分享保留当时确认的快照，需要工程师手动停用。新版本应重新生成、确认、创建分享。客户页及放大图保留“AI 效果预览”提示和最终以实际安装为准的声明；未实现像素级水印，脱离小程序的截图仍需沟通说明。

AI 不是工程制图软件，无法保证精确尺寸、真实受力安全、多个角度自动一致；必须保留工程师复核。通过 3 个真实项目的质量验证后，再决定是否需要多参考图模型、统一场景或后续视频能力。

### 结构方案录入与兼容

“编辑安装位置”现支持分面、分格、转角关系、开启方式与方向、局部避让、玻璃、五金与禁止改变项。尺寸单位统一为毫米；新增安装面或分格默认不填尺寸，开启方式默认“待工程师确认”，不得根据本批参考图猜测填写。新方案最多 6 个面、每面 12 个分格，未录完整可先保存草稿。

提交生图前，有结构面的方案必须补齐各面与分格宽高、开启方式、非固定格的方向说明，以及第二个面起的相邻关系。此检查仅针对字段完整性，不进行尺寸闭合、结构安全或施工校验。旧的纯文字结构方案保持兼容，确认页会特别提示没有分面分格记录，工程师需人工核对文字是否完整。

确认页通过 `engineer-api.getGenerationPreview` 只读获取当前结构摘要及临时图片地址，不调用模型。`createGeneration` 必须提交同一方案 / 资料摘要和四项确认；摘要过时会拒绝入队。任务冻结已确认结构快照，后续编辑不会修改在途任务的输入。修改分格或材料后，旧失败任务不能直接重试，应重新确认当前方案创建任务；旧版本效果图也不能用于创建新分享。

升级时先执行 `npm run sync:domain` 并部署新版 `engineer-api`，再使用新版小程序；生图 Worker 在启用前也需要更新，以便将分面分格摘要写入提示词。不要让旧客户端继续调用缺少确认摘要的 `createGeneration`。

## 5. 发布真实案例与维护店铺资料

首版没有公开内容管理后台。管理员在控制台更新 `store_config/main` 的微信号、营业时间，二维码先上传 `public/`，填 `cloud://.../public/...` 文件 ID。不要把私有照片移入公开区以绕过权限。

案例发布前先获得展示许可、清理门牌和人员等隐私。照片放 `public/cases/案例ID/`，在 `cases` 添加记录。以下是字段模板，**不是可发布的真实案例**：

```json
{
  "_id": "case-001",
  "title": "真实项目名称",
  "summary": "实际安装与产品说明",
  "community": "获得允许展示的小区名称，可留空",
  "categoryIds": ["railings", "windows"],
  "coverImage": "替换为真实的 cloud://.../public/... 文件ID",
  "images": ["替换为真实的 cloud://.../public/... 文件ID"],
  "locations": [{ "name": "阳台", "products": ["不锈钢栏杆"], "material": "实际材料" }],
  "status": "draft",
  "publishedAt": "替换为正式发布时间的 ISO 字符串"
}
```

案例 `_id` 使用唯一的英文字母、数字、下划线或连字符（最多 100 字符）。检查真实资料后才将 `status` 改为 `published`。`categoryIds` 允许 `railings`、`windows`、`canopies`、`sunrooms`、`gates`、`accessories`；允许一项目关联多类。不能把 AI 效果图冒充完工实景案例。下架将 `status` 改为 `draft`，不必删除记录。

## 6. 本地验证与上线门槛

```sh
npm ci
npm run sync:domain
npm run build:content
npm run typecheck
npm test
npm run check
```

本地自动化测试使用隔离的内存数据库和假 Provider，不连接腾讯 AI、不收费，也不能代替云端实际验收。检查工具能发现 JSON 模块误导入、页面缺失、WXML / WXSS 编译错误和主包源文件超限，但最终上传包体积以微信开发者工具为准。

上线前至少完成：

- 关闭本地预览依赖，在正式版本确认接口失败时有明确错误提示。
- 真机检查四个公共页面、业务详情、拨号 / 取消拨号、微信信息与分享进入。
- 用不同微信身份验证工程师越权、私有素材拒绝直读、未审核图片不可分享。
- 完成真实上传 → 生成 → 审核 → 分享 → 停用全链路，检查资源消耗与日志。
- 补齐小程序类目、隐私保护指引及上传 / 相机相关声明；核对现行 AI 内容标识与平台审核要求。当前本地 UI 标签不能视为全部合规事项已完成。
- 当前 `sitemap.json` 全部禁止索引以保护开发阶段；上线时只对公开页面评估开放，工程师 / 专属分享页继续禁止。
- 建议正式客户使用前创建单独生产环境并逐项初始化，开发与正式环境不要混用客户资料；当前代码仍只指向用户给定的 `cloud1`。

未完成真实 AI 质量验证或资源未开通时，可以先发布不含 AI 对客承诺的公共展示阶段，但工程师功能仍须完成权限配置，不应向顾客声称“自动精确还原方案”。
